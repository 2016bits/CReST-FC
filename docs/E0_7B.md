# Frozen Qwen2.5-7B E0 direct verdicts

`scripts/run_e0_7b.sh` evaluates the exact Qwen2.5-7B-Instruct snapshot used by `fever7b_e1_main`. The launcher checks both the model snapshot and FEVER dev source hash against the E1 manifest. Model weights remain frozen and no Probe, adapter, or LoRA checkpoint is loaded.

The E0 prompts and label mappings are the existing ones: FEVER asks for `SUPPORTS`, `REFUTES`, or `NEI`; HOVER, PolitiHop, symmetric-PolitiHop, and symmetric-FEVER ask for `SUPPORTED` or `NOT_SUPPORTED`, which map to canonical `SUPPORTS` and `REFUTES`. FEVER dev contains only SUPPORTS/REFUTES gold labels, so its three-label metric is an evaluation on a two-class subset. Set `FEVER_BINARY=1` for a separate FEVER prompt that outputs exactly `SUPPORTS` or `REFUTES`, matching the E1 label meanings.

The 7B E0 mode generates a verdict with deterministic decoding. Generation stops when a complete permitted label appears, at the first newline, or after eight new tokens. The raw continuation is saved; only a complete permitted label, with surrounding whitespace removed, is accepted. Anything else becomes `INVALID` and contributes to the invalid-output rate. This checks the model's actual response format, whereas the earlier 0.5B E0 used teacher-forced candidate scores. The two protocols must be reported separately.

```bash
# All five datasets, all examples, full Claim + Evidence input.
GPU_TOKENS=1,2,3,4,5 bash scripts/run_e0_7b.sh e0_qwen7b_full

# Resume the same run after a stopped GPU process.
RESUME=1 GPU_TOKENS=1,2,3,4,5 bash scripts/run_e0_7b.sh e0_qwen7b_full

# Optional Claim-only and Evidence-only ablations (new run ID).
CONDITIONS=full,claim_only,evidence_only GPU_TOKENS=1,2,3,4,5 \
  bash scripts/run_e0_7b.sh e0_qwen7b_ablations

# Auxiliary binary FEVER result matching the E1 SUPPORTS/REFUTES label space.
DATASETS=fever GPU_TOKENS=4 FEVER_BINARY=1 CONDITIONS=full \
  bash scripts/run_e0_7b.sh e0_qwen7b_fever_binary

# Small wiring check; the first 20 source rows are not a balanced estimate.
LIMIT=20 CONDITIONS=full GPU_TOKENS=1,2,3,4,5 \
  bash scripts/run_e0_7b.sh e0_qwen7b_smoke
```

Each dataset writes `data/samples.jsonl`, `e0/predictions.jsonl`, `e0/metrics_<condition>.json`, and a log in `outputs/experiment_runs/<run-id>/<dataset>/`. The run root contains `launcher_manifest.json` with the E1 snapshot pin. Generated predictions append one complete JSONL record at a time and are reused on resume. The logs show progress every 100 examples. A resumed run can assign different GPUs through `GPU_TOKENS`; the launch history records each assignment. The five-dataset full run can be audited with:

```bash
PYTHONPATH=src /data/yangjun/.conda/envs/crestfc/bin/python \
  scripts/audit_e0.py --run-id e0_qwen7b_full
```

The direct verdict result measures the frozen model's behavior under the E0 prompt. E1 Probe Macro-F1 measures what a separately fitted classifier can read from internal states. Their F1 values answer different questions and should not be subtracted as a model-performance gain or loss.
