# E2: frozen Qwen2.5-7B causal tracing

The implementation is `src/crestfc/e2_7b.py`; the launcher is `scripts/run_e2_7b.sh`. It reuses the exact Qwen snapshot and original E1 full Probe bundles. It never updates the model or the Probes. Layer numbers are zero based. The normal run scans all 28 block outputs; L18–L23 also receive local Probe-axis, orthogonal, non-relation-token, and answer-token interventions.

## Pair source and review

The default source is the independent VitaminC **dev** pair file from E1.5. A pair has one unchanged Claim, a SUPPORTS Evidence, and a REFUTES Evidence. The source labels have **not** been human-verified. The preparation step therefore requires a review JSONL unless `ALLOW_UNREVIEWED=1` is set for an exploratory pilot. Every approved record needs `pair_id`, a nonempty `reviewer`, and `approved`, `claim_unchanged`, `evidence_changed`, `supports_label_correct`, `refutes_label_correct`, and `evidence_sufficient` all set to `true`. The generated `review_queue.jsonl` supplies the review template. Use a **new run ID** after creating a review file; a run manifest is immutable. E3 layer selection is disabled for unreviewed pairs.

To export the full VitaminC dev review queue without using a GPU, run `PYTHONPATH=src /data/yangjun/.conda/envs/crestfc/bin/python -m crestfc.e2_7b prepare --run-id e2_review_queue --max-pairs 0 --allow-unreviewed`. Review `outputs/experiment_runs/e2_review_queue/review_queue.jsonl`, then pass an approved review file to a **different** run ID.

```bash

  GPU_TOKENS=0,1,2,4 bash scripts/run_e2_7b.sh e2_vitaminc_test
```

For a short GPU wiring check, use `LAYERS='4 8 12 18 19 20 21 22 23 27'` with a distinct run ID. Every run must include L18–L23. A failed shard can be resumed with the identical command; completed pair results are reused. Logs are in `outputs/experiment_runs/<run-id>/logs/`.

## Intervention and outcome

The E1 input ends at `Relation anchor:`. A fixed answer instruction is appended *after* that anchor, and tokenization is checked to preserve every E1 prefix token. The state at the E1 anchor is captured in the **same padded two-candidate forward shape** used for decision scoring; this avoids BF16 shape-dependent differences in the same-input control. Autoregressive causality prevents the later answer text from changing the mathematical information available at the anchor. The model's forced-choice output is the **sum of teacher-forced token log probabilities** for ` SUPPORTS` and ` REFUTES`; this is an output decision distribution, not free-form generation. Its binary prediction chooses the larger score. The baseline is measured separately for each Evidence.

For both SUPPORTS→REFUTES and REFUTES→SUPPORTS, a hook replaces the target anchor state at one layer with the source state. The indirect effect is the change in the log-probability margin toward the **source** label. Positive values mean that the patch moves the final decision toward the donor Evidence's relation. The same-input control replaces the target state with its own separately captured state. The random-sample control draws a different Claim. The wrong-relation control draws a different Claim with the target relation. L18–L23 additionally patch the component parallel to the original E1 full-Probe decision vector, its orthogonal complement, the first token, or the last answer-prefix token. The answer-token patch has its own same-input control and tests whether a late readout position is causally sensitive when the E1 anchor is weak. These controls test whether a favorable effect is specific to the relation and token position; they do not prove a pure semantic circuit.

`analysis/baseline.jsonl` stores clean predictions and margins. `analysis/causal_effects.jsonl` stores every patch score and IE. `analysis/causal_summary.csv` reports all pairs, each patch direction, clean-correct pairs, and token-length-matched pairs. `analysis/causal_layer_profile.png` plots the source IE, controls, and E1 Macro-F1 curve. Intervals use source-family clustered bootstrap; both patch directions for a pair stay in the same resampled family. `analysis/e2_report.json` compares E1 Macro-F1 with causal scores across scanned layers (Spearman correlation), lists Probe-correct/model-wrong counts, and records same-input checks. `analysis/e3_layer_selection.json` contains dev-only candidates. A layer qualifies only if its source IE and paired source-minus-absolute-random IE both have positive family-bootstrap lower bounds **in both directions separately and overall**, the minimum pair count is reached, all pairs are reviewed, and same-input error stays below the declared tolerance. Clean-correct pairs are reported separately because strong relation influence can coexist with a wrong clean decision. Test runs require a frozen, eligible dev selection and never select or re-rank E3 layers.

The analysis is conditional on this fixed answer suffix, label verbalizers, and paired source distribution. Causal patching at a block output shows an effect on this output metric; it does not establish that the layer exclusively stores the relation. If no clean-correct pairs remain, the output effects still describe causal sensitivity, while clean-accuracy-conditioned conclusions are unavailable. Formal claims require reviewed pairs, enough independent families, and repetition across datasets or seeds.

The intervention and metric choices follow the cautions in [Zhang and Nanda, *Towards Best Practices of Activation Patching in Language Models*](https://arxiv.org/abs/2309.16042) and [Heimersheim and Nanda, *How to use and interpret activation patching*](https://arxiv.org/abs/2404.15255): patch effects depend on the chosen output metric, donor distribution, and patch location.
